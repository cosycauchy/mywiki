# 서버 없는 나무위키 스타일 개인 위키

`docs/` 폴더에 `.namu` 파일을 넣으면 나무위키처럼 생긴 정적 웹사이트가 만들어집니다.
GitHub에 올리면 자동으로 빌드·배포되고, 링크 하나로 폰이든 PC든 어디서나 볼 수 있습니다.

- 서버 없음 · 비용 0원 · DB 없음
- 파이썬 표준 라이브러리만 사용 (설치할 패키지 없음)

---

## 1. 처음 한 번만 (약 10분)

### 1-1. GitHub 저장소 만들기

1. github.com 가입 → 우측 상단 **+ → New repository**
2. 이름은 아무거나 (예: `mywiki`), **Private** 선택해도 됩니다
3. **Create repository**

### 1-2. 이 폴더를 올리기

내 컴퓨터 터미널에서:

```bash
cd mywiki
git init
git add .
git commit -m "첫 위키"
git branch -M main
git remote add origin https://github.com/내아이디/mywiki.git
git push -u origin main
```

> 터미널이 부담스러우면 저장소 페이지의 **Add file → Upload files** 로 폴더를 드래그해도 됩니다.

### 1-3. Pages 켜기

저장소 → **Settings → Pages → Source**를 **GitHub Actions**로 변경.

1~2분 뒤 `https://내아이디.github.io/mywiki/` 에서 위키가 열립니다.
이 주소를 폰 홈 화면에 추가해두면 앱처럼 쓸 수 있습니다.

### 1-4. config.json 고치기

```json
{
  "site_name": "내 위키 이름",
  "front_page": "FrontPage",
  "github_repo": "내아이디/mywiki",
  "github_branch": "main"
}
```

`github_repo`를 채워야 문서 상단에 **편집 / 역사** 버튼이 생깁니다.

## 2. 평소 사용법

### 글 쓰기 — 브라우저에서

- 기존 문서: 문서 상단 **✏ 편집** 버튼 → GitHub 편집창 → 고치고 **Commit changes**
- 새 문서: 없는 문서로 걸린 빨간 링크를 만들어두거나, 저장소의 `docs/` 폴더에서 **Add file → Create new file** → 이름을 `문서이름.namu` 로

저장 후 **1~2분** 기다리면 사이트에 반영됩니다. 폰 브라우저에서도 똑같이 됩니다.

### 글 쓰기 — 내 컴퓨터에서

`docs/` 에 `.namu` 파일을 만들고:

```bash
python build.py          # dist/ 에 결과물 생성
cd dist && python -m http.server 8080   # http://localhost:8080 에서 미리보기
```

확인 후 `git add . && git commit -m "수정" && git push`

## 3. 문법 (나무마크)

```
[목차]                          목차 자동 생성
== 문단 ==                      === 소문단 ===  ==== 더 작은 문단 ====
'''굵게'''  ''기울임''  __밑줄__  ~~취소선~~
[[다른문서]]                    [[다른문서|보일 이름]]
[[https://주소|링크 이름]]      외부 링크
[[분류:카테고리]]                문서 상단 분류바 + 분류 페이지 자동 생성
각주를 답니다.[* 하단에 모입니다.]
 * 목록                         (줄 앞에 공백 한 칸 이상 — 두 칸이면 하위 항목)
 1. 번호 목록
|| 표 || 헤더는 '''굵게''' ||
|| 칸 || 칸 ||
> 인용문
----                            수평선
{{{ 코드블록 }}}
{{{#!folding [펼치기 · 접기]
접히는 내용
}}}
```

없는 문서로 링크를 걸면 **빨간 링크**가 됩니다. 일단 링크부터 마구 걸어두고 나중에 채우는 것이 위키를 굴리는 요령입니다.

## 4. 기본으로 들어있는 기능

| 기능 | 설명 |
|---|---|
| 검색 | 상단 검색창. 서버 없이 브라우저에서 전체 문서 본문 검색 |
| 다크 모드 | 우측 ☾ 버튼. 시스템 설정 자동 감지 |
| 분류 | `[[분류:이름]]` 만 쓰면 분류 페이지가 알아서 생김 |
| 편집 이력 | GitHub이 모든 수정을 영구 기록. 문서 상단 **역사** 버튼 |
| 백업 | 별도 설정 불필요. Git 저장소 자체가 백업 |
| 모바일 | 반응형. 폰에서도 그대로 |

## 5. 남에게 안 보이게 하기

### 가장 간단한 방법

저장소를 **Private**으로 두고, GitHub Pages 대신 **Cloudflare Pages**로 배포한 뒤
Cloudflare Zero Trust의 **Access** 정책으로 내 이메일만 허용하면 됩니다. 무료 플랜으로 가능합니다.

### 대충 가려두기만 해도 될 때

GitHub Pages는 무료 플랜에서 사이트가 공개됩니다. 다만:

- 모든 페이지에 `noindex` 태그가 이미 들어 있어 검색엔진에는 안 잡힙니다
- 저장소 이름을 추측하기 어렵게 지으면 사실상 아무도 찾지 못합니다

민감한 내용을 넣을 거라면 위의 Cloudflare Access 방식을 쓰세요.

## 6. 폴더 구조

```
mywiki/
├── build.py                    빌더 (건드릴 일 거의 없음)
├── config.json                 사이트 이름, 저장소 주소
├── docs/                       ← 여기에 글을 씀
│   ├── FrontPage.namu
│   └── 읽은 책.namu
├── dist/                       빌드 결과 (자동 생성, git에 안 올라감)
└── .github/workflows/deploy.yml   푸시하면 자동 배포
```

문서 파일 이름이 곧 문서 제목입니다. 띄어쓰기를 그대로 써도 됩니다.

---

## 7. 나중에 마음이 바뀌면

`.namu` 파일들은 그냥 텍스트라 어디로든 옮길 수 있습니다.
나중에 openNAMU 같은 서버형 위키로 갈아타고 싶어지면 파일을 그대로 붙여넣으면 됩니다.
문법이 거의 같아서 옮기는 비용이 거의 없습니다.
